# Эксплуатация

## Требования

- **Node.js 20+** (проверено на 22.13). Внешних зависимостей нет.
- Windows 10/11 — для ярлыка и нотификатора; сам сервер кроссплатформенный.
- Браузер с поддержкой `EventSource` (все современные; есть fallback на опрос).
- Клиент EVE Online на той же машине — для чтения чат-логов.

## Установка

```bash
git clone https://github.com/Indarli/eve-flip-scanner.git
cd eve-flip-scanner
node server.mjs
```

Откройте <http://127.0.0.1:8787>.

### Первичная настройка

1. Создайте приложение на <https://developers.eveonline.com>:
   - Callback URL: `http://127.0.0.1:8787/callback`
   - Scopes: см. [SECURITY.md](SECURITY.md).
2. Скопируйте **Client ID**.
3. В приложении: «Настройки» → Client ID → сохранить.
4. «Войти через EVE» — авторизуйте персонажа. Можно добавить несколько.
5. Для интеля: «Интел» → выберите каналы (папка логов определяется автоматически).

## Запуск на Windows

| Файл | Что делает |
|---|---|
| `start.cmd` | запускает сервер и нотификатор (то же, что ярлык) |
| `toggle.vbs` | переключатель: первый клик — запуск, второй — остановка |
| `stop.cmd` | принудительно останавливает сервер и нотификатор |
| `notifier.vbs` | запускает окно-нотификатор |
| `server.vbs` | запускает сервер скрыто (без консоли) |

На рабочем столе создаётся ярлык **«EVE Flip Scanner»**, который вызывает `toggle.vbs`.
Консоль держать открытой не нужно.

### Автозапуск с Windows

1. `Win+R` → `shell:startup`.
2. Положите туда ярлык «EVE Flip Scanner».

## Docker

```bash
docker build -t eve-flip-scanner .
docker run -d --name eve-flip -p 8787:8787 -v "$PWD/data:/app/data" eve-flip-scanner
```

- Порт публикуется на `127.0.0.1` (не открывайте наружу без необходимости).
- Каталог `data/` монтируется томом, иначе токены и конфиг пропадут при пересоздании.
- Нотификатор в контейнере не работает (это Windows-приложение).

## Обновление

```bash
git pull
# перезапустить: второй клик по ярлыку (стоп), затем первый (старт)
```

Перед обновлением можно сделать бэкап: «Настройки → Создать копию».
После обновления проверьте `/api/health` — там версия.

## Логи

- Сервер пишет в консоль. При запуске через ярлык консоли нет —
  для отладки запустите `node server.mjs` в терминале.
- Ошибки авторизации видны в консоли: `[auth] …`.
- Ошибки профиля: `[character] refresh <id> failed: …`.

## Диагностика

| Симптом | Причина и решение |
|---|---|
| `EADDRINUSE` | порт занят. Запустите `stop.cmd` или смените `PORT`/`config.server.port` |
| После входа «не авторизован» | callback не совпадает с настройкой приложения; проверьте `callbackUrl` и порт |
| Callback «висит» | используйте ручную вставку URL: `POST /api/auth/manual` или форма в настройках |
| Пустой интель | не выбран канал, неверная `chatDir`, персонажи офлайн или логи не пишутся |
| Прыжки `…` долго | ESI не отвечает; проверьте баннер ESI и кнопку «Пересчитать» |
| Нет алертов | все ваши персонажи офлайн — прыжки не считаются (это by design) |
| Портфель пуст | нет ордеров/транзакций/ассетов, либо профиль ещё грузится |
| В складе `структура #id` | приватная структура, ESI вернул 403 — название недоступно |
| Скрипты PowerShell не запускаются | политика ExecutionPolicy; запускайте через `.vbs`/`.cmd` из проекта |
| Два окна нотификатора | старые экземпляры; `stop.cmd` завершит все, затем запустите снова |
| ESI-баннер не исчезает | нажмите «Повторить» или подождите авто-проверку (15 с) |

## Сброс

- **Сбросить скан**: удалить `data/results.json` и `data/scan-meta.json`.
- **Сбросить кэш ESI**: остановить сервер, удалить `data/cache/`.
- **Полный сброс**: удалить `data/` (потеряются токены, конфиг, история) — сервер создаст заново.

## Производительность

- Скан пяти хабов: обычно 1–3 минуты (зависит от `historyBudget`).
- Портфель: первый расчёт 3–10 секунд, далее из кэша.
- Интель: снапшот каждые 2 секунды по SSE, без нагрузки на ESI при отсутствии новых событий.
- Память: обычно 80–200 МБ; растёт с числом событий интеля (ограничено 200 строками).

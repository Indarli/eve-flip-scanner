# Архитектура

## Общая схема

```
┌────────────────────────────── Браузер ──────────────────────────────┐
│  public/index.html + app.js + style.css                             │
│  вкладки: Сканер · Портфель · Интел · Планетарка · Персонажи · Настройки │
└───────────────▲───────────────────────────────┬────────────────────┘
                │ SSE /api/events                │ fetch /api/*
                │ (intel, scan, esi)             │
┌───────────────┴───────────────────────────────▼────────────────────┐
│                        server.mjs (HTTP, ESM)                       │
│  маршрутизация · SSE-хаб · сканы · портфель · PI · интель · бэкапы  │
└───┬───────────────┬────────────────┬────────────────┬──────────────┘
    │               │                │                │
 lib/esi.mjs    lib/scan.mjs     lib/intel.mjs    lib/character.mjs
 (лимиты,       (конвейер       (чаты, zKill,     (SSO-профиль,
  кэш, retry)    рынка)          маршруты)         ассеты, ордера)
    │               │                │                │
    └───────────────┴────── ESI / zKillboard / Fuzzwork ──────────────┘
```

Нотификатор в углу экрана — отдельный процесс PowerShell (`notifier.ps1`), который
опрашивает `/api/notifier/alerts` и показывает карточку поверх окон.

## Модули

| Файл | Ответственность |
|---|---|
| `server.mjs` | HTTP-сервер, маршруты, SSE, оркестрация сканов, портфель, бэкапы, запуск интеля |
| `lib/esi.mjs` | Клиент ESI: ETag-кэш, лимиты, повторные попытки, токены, статистика ошибок |
| `lib/auth.mjs` | EVE SSO (OAuth2 + PKCE), хранение и обновление токенов, несколько персонажей |
| `lib/store.mjs` | Конфиг, пути `data/`, атомарная запись JSON, бэкапы, список чатов |
| `lib/character.mjs` | Профиль персонажа: кошелёк, скиллы, стендинги, ордера, ассеты, структуры, колонии |
| `lib/scan.mjs` | Сканирование рынка: стаканы, история, агрегация, скоринг, результаты |
| `lib/fees.mjs` | Формулы налогов и брокерских комиссий, экономика флипа |
| `lib/intel.mjs` | Чтение чат-логов, разбор сообщений, имена, прыжки, zKillboard, снапшоты |
| `lib/pi.mjs` | Анализ планетарных колоний, экстракторов и очереди перезапуска |
| `lib/portfolio.mjs` | P&L по транзакциям, склад, котировки Fuzzwork, проверка ордеров |

## Потоки данных

### Сканирование рынка

1. `POST /api/scan` запускает `startScan()` (одна задача за раз).
2. Сканер собирает стаканы выбранных NPC-хабов (`/markets/{region_id}/orders/`) и структур
   (`/markets/structures/{structure_id}/`, нужен токен).
3. Для отобранных пар (тип, регион) подтягивается история (`/markets/{region_id}/history/`)
   в пределах `historyBudget`.
4. Результат считается, сохраняется в `data/results.json` и отдаётся через `/api/results`.
5. Прогресс транслируется событием SSE `scan` (или опросом `/api/scan/status` как fallback).

### Обновления интерфейса

- **SSE** `GET /api/events` — основной канал. События:
  - `intel` — снапшот интелидженса (раз в 2 с);
  - `scan` — состояние скана (при изменениях и раз в 2 с, пока идёт);
  - `esi` — состояние доступности ESI.
- **Fallback** — если `EventSource` недоступен или соединение оборвалось, клиент
  переключается на прежний опрос (интель 2 с, скан 800 мс, ESI 5 с).
- **Keep-alive** — комментарий `: ping` раз в 20 секунд.

### Портфель

1. Профиль персонажа обновляется фоново (`refreshCharacter`) и сохраняется в
   `data/characters.json`.
2. `GET /api/portfolio?char=<id>` собирает:
   - котировки ордеров (Fuzzwork, по станции или региону);
   - P&L по транзакциям (метод средней стоимости);
   - склад, агрегированный по типу и корневой локации (контейнеры разворачиваются до станции).
3. Результат кэшируется на 60 секунд отдельно по каждому персонажу.

## Кэши

| Что | Где | Время жизни |
|---|---|---|
| Ответы ESI (ETag) | `data/cache/*.json` | до истечения `Expires`, проверка по ETag |
| История цен | в памяти + `data/cache` | на время процесса/ETag |
| Имена типов/систем | память (`namesCache`, `systems`) | на время процесса |
| Маршруты прыжков | память (`routeCache`) | успех — 30 мин, ошибка — 1 мин |
| Локации склада | память (`locationCache`) | 6 часов |
| Портфель | память, по персонажу | 60 секунд |
| Котировки хабов (сравнение) | память (`compareCache`) | 60 секунд |
| Колонии PI | память + `data/pi-cache.json` | до ручного обновления |
| Скан | `data/results.json` | до следующего скана |

## Обработка ошибок

- `lib/esi.mjs` повторяет запросы при сети/5xx/420/429, соблюдая `Retry-After`.
- Серия ошибок (≥3) помечает ESI как недоступный: в интерфейсе появляется баннер,
  сервер сам проверяет `/status/` каждые 15 секунд.
- Ошибки профиля персонажа не ломают остальных: каждый персонаж обновляется независимо.
- Резолв структур ограничен по времени и количеству, чтобы не блокировать профиль.
- Если браузер не поддерживает SSE — интерфейс продолжает работать на опросе.

## Запуск и остановка

- `server.mjs` инициализирует каталоги `data/`, загружает конфиг, персонажей и кэш,
  поднимает HTTP-сервер на `127.0.0.1:8787` (настраивается).
- Windows-обёртки: `start.cmd` / `toggle.vbs` — первый клик запускает сервер и нотификатор,
  второй останавливает; консоль не нужна.
- Корректная остановка — завершение процесса; данные пишутся атомарно (временный файл + rename).

## Ограничения по данным

- ESI не отдаёт локацию и онлайн чужих персонажей — интель работает только по чат-логам.
- Приватные структуры могут отвечать `403` — в складе показывается `структура #id`.
- У ESI нет методов записи для планетарки — «перезапуск» в приложении это чек-лист,
  а не игровое действие.

# Данные и файлы

Всё состояние приложения лежит в `data/` рядом с `server.mjs`. Каталог **не коммитится**
(исключён `.gitignore`), потому что содержит токены и кэш.

```
data/
├── config.json          конфигурация (см. CONFIG.md)
├── tokens.json          токены SSO по персонажам (чувствительно!)
├── characters.json      профили персонажей: кошелёк, ордера, ассеты, транзакции
├── results.json         последний результат скана
├── scan-meta.json       метаданные скана (время, локации)
├── names.json           кэш имён (типы, системы, персонажи)
├── pi-cache.json        кэш планетарки (схемы, колонии)
├── sound.wav            пользовательский звук оповещения (если загружен)
├── logs/                app-YYYY-MM-DD.log (14 дней)
├── notifier-heartbeat.json  отметка жизни нотификатора (pid, время)
├── backups/             автобэкапы config/tokens/characters
└── cache/               ETag-кэш ответов ESI (много мелких JSON)
```

## tokens.json

```json
{
  "characters": {
    "12345678": {
      "access_token": "…",
      "refresh_token": "…",
      "expires_at": 1794921987804,
      "character_id": 12345678,
      "character_name": "Pilot Alpha",
      "scopes": ["esi-wallet.read_character_wallet.v1", "…"],
      "updated_at": "2026-11-17T…"
    }
  }
}
```

- Токены обновляются автоматически по `refresh_token`.
- Если обновление не удалось, персонаж помечается как требующий повторного входа.
- **Никогда не публикуйте этот файл.** В бэкапах он тоже есть.

## characters.json

Профиль каждого персонажа содержит:

| Поле | Описание |
|---|---|
| `characterId`, `name`, `wallet` | идентификация и кошелёк |
| `skills`, `fees` | уровни навыков, рассчитанные налог/брокер по хабам |
| `orders`, `ordersList` | сводка и детальные активные ордера |
| `assetTotals`, `assetStacks` | склад по типам и по типу+корневой локации |
| `transactionsStats` | P&L: строки по типам и итоги |
| `structures` | известные структуры (из ордеров, ассетов, конфига) |
| `colonies` | планетарные колонии |
| `online` | онлайн-статус (если выдан scope `read_online`) |
| `updatedAt` | когда профиль обновлялся |

`assetStacks` хранит **корневую** локацию: если предмет лежит в контейнере или в корабле,
цепочка `location_id` разворачивается до станции/структуры.

## results.json

Результат последнего скана: массив строк и метаданные (время, список локаций).
Используется вкладкой «Сканер» и портфелем для котировок.

## cache/

ETag-кэш ESI: имя файла — хэш URL, содержимое — `{ headers, body, ts }`.
Можно безопасно удалить при остановленном сервере: данные перезагрузятся с ESI.
Не удаляйте при активном скане — это лишь замедлит его.

## backups/

Создаются автоматически:

- через 5 секунд после изменения `config.json`, `tokens.json` или `characters.json`;
- раз в сутки;
- при старте сервера;
- вручную кнопкой «Создать копию» (Настройки → Резервные копии).

Имена: `<имя>-YYYYMMDD-HHMMSS.json`. Хранятся последние **10** копий каждого файла.
Перед выходом из аккаунта токены сохраняются в бэкап, затем удаляются из `tokens.json`.

### Восстановление

1. Остановите сервер (`stop.cmd` или второй клик по ярлыку).
2. Скопируйте нужный файл из `data/backups/` в `data/` под исходным именем:
   `config-…json` → `config.json`, `tokens-…json` → `tokens.json`,
   `characters-…json` → `characters.json`.
3. Запустите сервер.

## Что можно удалять

| Файл | Последствия удаления |
|---|---|
| `cache/` | безопасно; ESI-данные загрузятся заново |
| `results.json`, `scan-meta.json` | пропадёт последний скан |
| `names.json` | имена подтянутся заново (медленнее первый раз) |
| `pi-cache.json` | колонии перезагрузятся с ESI |
| `characters.json` | профили перезагрузятся (если токены живы) |
| `config.json` | сброс к значениям по умолчанию (нужно заново ввести Client ID) |
| `tokens.json` | потребуется повторный вход через EVE |
| `backups/` | пропадёт история копий; на работу не влияет |
| `logs/` | пропадёт история логов; новые появятся заново |

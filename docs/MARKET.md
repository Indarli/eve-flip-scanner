# Сканер рынка

## Что делает

Ищет краткосрочные возможности «купить по биду — продать по аску» на пяти NPC-хабах
и в структурах, считает прибыль **после комиссий** и ранжирует по ожидаемому ISK/день.

## Конвейер скана

1. **Стаканы NPC-хабов** — `/markets/{region_id}/orders/?order_type=all` для каждого
   включённого хаба (Jita, Amarr, Dodixie, Rens, Hek).
2. **Стаканы структур** — `/markets/structures/{structure_id}/` (нужен токен и доступ).
   Структуры берутся из конфига и профиля персонажа.
3. **Агрегация** — по каждой паре (тип, локация) считаются лучший бид, лучший аск,
   глубина, конкуренция у лучшей цены.
4. **Предварительный отбор** — отсекаются пары с абсурдным спредом, нулевой глубиной
   и подозрительно низким объёмом.
5. **История** — для отобранных пар в пределах `historyBudget` подтягивается
   `/markets/{region_id}/history/` и считается VWAP за 30 дней, волатильность, объём.
6. **Расчёт и скоринг** — см. ниже; результат пишется в `data/results.json`.
7. **Прогресс** — SSE-событие `scan` (или `/api/scan/status`).

Одновременно выполняется только один скан; повторный запуск вернёт `409`.

## Комиссии

Формулы из `lib/fees.mjs` (актуальны на 11.2026):

```
Sales tax   = 7.5% × (1 − 0.11 × Accounting)                 // макс. 3.375% при V
Broker (NPC)= 3% − 0.3% × BrokerRelations
                 − 0.03% × factionStanding
                 − 0.02% × corpStanding                       // минимум 1%
Broker (структура) = 0.5% SCC + ставка владельца
```

- Налог считается по навыку `Accounting` персонажа.
- Брокер для NPC-хаба — по стендингам к фракции/корпорации владельца станции.
- Для структур скиллы не работают: используется ставка владельца из конфига
  (или `defaultStructureTax`).

### Экономика флипа

```
buyCost      = bid × (1 + broker)
sellNet      = exitPrice × (1 − tax − broker)
profitUnit   = sellNet − buyCost
marginNet    = profitUnit / buyCost
breakEvenAsk = buyCost / (1 − tax − broker)
```

## Консервативная цена выхода

Сканер не верит «мечтательному» лучшему аску. Цена выхода:

```
exitPrice = min(ask, max(VWAP30, bid))
```

То есть продавать планируется не выше VWAP и не ниже текущего бида.
Дополнительно вводится ограничение по объёму: `volumeDay × capture` — сколько единиц
реалистично продать за день.

## Поля результата

| Поле | Смысл |
|---|---|
| `bid`, `ask` | лучшие цены в стакане локации |
| `spreadPct` | грязный спред `(ask − bid) / bid` |
| `marginNet` | нетто-маржа после комиссий с консервативной ценой выхода |
| `marginBook` | оптимистичная маржа по стакану (справочно) |
| `exitPrice` | расчётная цена продажи |
| `profitUnit` | прибыль на единицу |
| `breakEvenAsk` | цена, при которой флип выходит в ноль |
| `volumeDay` | средний объём в день (история региона) |
| `iskVolumeDay` | объём в ISK |
| `iskDay` | ожидаемая прибыль в день с учётом `capture` |
| `roiDay` | `iskDay / capital` |
| `daysToSell` | оценка оборота позиции |
| `competition` | число ордеров у лучшей цены |
| `capital` | сколько нужно вложить |
| `depthAsk` | глубина sell-стакана (5 уровней) |
| `volatility` | волатильность за 30 дней |
| `fair` | VWAP за 30 дней |
| `discountPct` | отклонение аска от VWAP |

## Фильтры

Серверные (`config.filters`): минимальная маржа, объём, цена.
Клиентские (вкладка «Сканер»): поиск, нетто %, объём/день, максимальная цена,
локация, тип рынка, «только прибыльные», «без SKIN/BP».
Пресеты фильтров сохраняются в браузере.

## CSV

Кнопка «CSV» экспортирует **текущую отфильтрованную** таблицу: `;` как разделитель,
UTF-8 с BOM (Excel открывает без танцев), числа с запятой.

## Сравнение хабов

В карточке товара — таблица bid/ask/спред по Jita, Amarr, Dodixie, Rens, Hek
(котировки Fuzzwork, кэш 60 секунд).

## Автоскан

Настройки → Автоскан: включить, интервал (мин), минимальная нетто-маржа.
Скан запускается сам, пока страница открыта. После завершения новые позиции выше порога
показываются карточкой в браузере и звуком. **В углу экрана уведомлений нет** —
это отдельный нотификатор для интеля.

## Ограничения

- Регионные ордера ESI **не содержат** ордеров игровых структур — они запрашиваются отдельно.
- История даётся по региону, а не по конкретной станции.
- Оценка объёма и оборота приблизительная: реальный филл зависит от конкуренции.
- Для структур без доступа ESI вернёт `403` — такие структуры не сканируются.
